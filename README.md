# Speexx Solve

คลังค้นหาโจทย์และเฉลยสำหรับทบทวนภาษาอังกฤษ มีหน้าแนะนำ การกรองระดับและประเภท แสดงผลตามลำดับบทเรียน และปุ่มคัดลอกเฉพาะแบบฝึกหัดที่ต้องพิมพ์คำตอบ ใช้งานฟรี เว็บไซต์นี้ไม่ใช่เว็บไซต์ทางการของ Speexx

## เริ่มใช้งาน

ติดตั้ง Node.js 18 ขึ้นไป แล้วรัน `npm start` จากโฟลเดอร์โครงการ เปิด `http://localhost:3000` ไม่สามารถเปิด HTML โดยตรงได้ เพราะการค้นหาทำงานบนเซิร์ฟเวอร์ รันการทดสอบด้วย `npm test`

## โครงสร้าง

- `public/` ไฟล์หน้าเว็บ ฟอนต์ Prompt และรูปที่เปิดสาธารณะ
- `public/js/config.js` แก้ชื่อ รูป และลิงก์เครดิต Facebook / Instagram (ใส่ URL จริงเพื่อเปิดเป็นลิงก์)
- `public/js/exercises.js` ประเภทแบบฝึกหัดและการแยกตัวเลือก
- `public/assets/favicon.png` ไอคอนบนแท็บเว็บ
- `api/search.js` API ค้นหา แสดงผลครั้งละ 20 รายการตามลำดับข้อมูลต้นฉบับ
- `server/data.json` ข้อมูลที่ API ใช้ ไม่ได้เปิดเป็นไฟล์สาธารณะในการตั้งค่า Vercel
- `server/dev.js` เซิร์ฟเวอร์สำหรับทดสอบในเครื่อง (ให้บริการเฉพาะ `public/` และ API)
- `solve data/` ไฟล์ JSON ต้นฉบับ
- `scripts/build-data.mjs` สร้าง `server/data.json` จากข้อมูลต้นฉบับด้วย `node scripts/build-data.mjs`
- `vercel.json` กำหนด route สำหรับ static files และ serverless API

## ความเป็นส่วนตัวของข้อมูล

การค้นหาฝั่งเซิร์ฟเวอร์ช่วยไม่ส่งไฟล์ข้อมูลทั้งหมดไปยังเบราว์เซอร์ และไม่เปิดเส้นทางตรงไปยังไฟล์ต้นฉบับบน deployment นี้ แต่ผลลัพธ์ที่แสดงต่อผู้ใช้ยังสามารถตรวจสอบและรวบรวมผ่าน API ได้ การปิด F12 ไม่ใช่มาตรการรักษาความปลอดภัย หากต้องการจำกัดการดึงข้อมูลจริงควรใช้บัญชีผู้ใช้ การจำกัดอัตราที่ระดับ shared infrastructure/WAF และเก็บข้อมูลในฐานข้อมูลส่วนตัว โดยไม่ใส่ข้อมูลลับใน repository สาธารณะ **repository นี้เป็นสาธารณะและมีข้อมูลต้นฉบับใน Git history อยู่แล้ว** การย้ายไฟล์ในเว็บไม่ได้ลบสำเนาที่เผยแพร่ไปก่อนหน้า ควรพิจารณาตั้ง repository เป็น private และจัดการประวัติ/สำเนาอย่างเหมาะสม

## Vercel

เชื่อม repository กับ Vercel และ deploy จาก branch ที่ต้องการ ตัวตั้งค่า `vercel.json` จะให้บริการเฉพาะไฟล์ใน `public/` และ API ใน `api/` ทดสอบว่า `/server/data.json`, `/solve%20data/answers_A1.json` และ `/data.js` ตอบ 404 หลัง deploy และตรวจสอบว่าการค้นหาและคัดลอกบน HTTPS ทำงานจริง อย่าตั้ง output directory เป็น repository root หรือเผยแพร่ `server/` และ `solve data/` เป็น static files

### ลดการดึงข้อมูลอัตโนมัติ

API ส่งเฉพาะฟิลด์ที่หน้าเว็บจำเป็นต้องใช้และไม่ส่งข้อมูลออกเสียง แต่ยังต้องส่งคำตอบที่ผู้ใช้ดูได้ การลดฟิลด์หรือการแสดงทีละ 20 รายการ **ไม่ใช่การป้องกันการเก็บเฉลย** และยังตรวจดู Response ใน DevTools ได้ตามปกติ

มีตัวจำกัด 30 คำขอต่อนาทีต่อ IP ภายในแต่ละ process และตอบ HTTP 429 พร้อม `Retry-After` แต่บน Vercel process อาจมีหลาย instance หรือถูกรีสตาร์ต จึงเป็นเพียงตัวช่วย best-effort **ไม่ใช่ rate limit ที่ใช้ร่วมกันหรือป้องกัน scraping ได้จริง** ผู้ใช้ที่แชร์ IP เดียวกันอาจถูกจำกัดร่วมกัน

ควรตั้ง [Vercel WAF rate limiting](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting) ด้วยตนเองสำหรับ production: เปิด Project → Firewall → Configure → New Rule; ตั้ง Request Path เป็น `/api/search`, action เป็น Rate Limit, key เป็น IP, fixed window 60 วินาที และเริ่มต้นที่ 30 requests พร้อม HTTP 429; ตรวจสอบ traffic และปรับตามการใช้งานจริงก่อน Publish กฎอาจนับรวมผู้ใช้หลัง IP เดียวกัน ตรวจสอบค่าใช้จ่าย ข้อจำกัดแพ็กเกจ และผลกระทบก่อนเปิดใช้งาน กฎนี้ไม่ได้ถูกเปิดอัตโนมัติจาก repository หรือ connector และต้องทดสอบหลังเปิดใช้งาน

สำคัญที่สุด: repository นี้เป็น public และทั้ง `solve data/` และ `server/data.json` รวมถึง Git history สามารถดาวน์โหลดได้โดยตรงจาก GitHub ตั้ง repository เป็น private หลังพิจารณาผลกระทบต่อ deployment และผู้ร่วมงาน และตรวจสอบ deployment เก่าหรือสำเนาที่เผยแพร่แล้ว การเปลี่ยนเป็น private ไม่สามารถเรียกคืนสำเนาที่ถูกดาวน์โหลดไปแล้วได้

## บทเรียนและข้อมูลซ้ำ

เมื่อเลือกระดับภาษาในคลัง จะมีตัวกรองบทเรียนเฉพาะระดับนั้น รายการบทแสดงเฉพาะบทที่มีหน้าคำตอบซึ่งเว็บไซต์แสดงได้ ไม่ใช่ทุกบทใน catalog ต้นฉบับ และข้อมูลเก่าที่ไม่ระบุบทจะแสดงเป็น “ข้อมูลนำเข้า (ไม่ระบุบท)” การเปลี่ยนระดับหรือล้างตัวกรองจะกลับไปเลือกทุกบทเรียน

ตรวจข้อมูล 2,593 หน้า: ไม่พบ ID ซ้ำ และไม่พบหน้าที่มีเนื้อหาและคำตอบเหมือนกันทั้งหมดภายในบทเดียวกัน แต่พบรายการนำเข้าเก่าที่เป็นสำเนาแบบตัดข้อความของหน้าซึ่งมีอยู่แล้วในบทจริง API จึงตัดรายการนำเข้าเก่าที่จับคู่ได้แน่ชัด 133 รายการออกจากผลค้นหา โดยเทียบระดับ ชื่อหน้า คำสั่ง ประเภท คำตอบ และข้อความโจทย์ที่ตรงกันเป็น prefix (อย่างน้อย 20 ตัวอักษร) พร้อมกำหนดให้จับคู่ได้กับหน้าปกติเพียงหน้าเดียว หากสำเนามีโจทย์ยาวกว่า จะใช้โจทย์ที่ครบกว่ากับหน้าของบทจริง ไฟล์ข้อมูลต้นฉบับไม่ได้ถูกลบหรือแก้ไข รายการที่กำกวมหรืออาจเป็นคนละข้อยังคงแสดงอยู่ และรายการที่ซ้ำกันข้ามบทหรือระดับไม่ได้ถูกลบเพียงเพราะมีข้อความเหมือนกัน
